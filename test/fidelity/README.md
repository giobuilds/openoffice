# OOXML fidelity harness

The measured programme from `docs/ROADMAP.md` section 4, in skeleton form. It runs in the
`linux-full-build` job after the smoke, against the office that job just built, and reports a
score per document and per feature. It never fails the job on low fidelity; it only fails when
the office cannot be started or the corpus is empty.

## What it measures today

The office's OOXML filters are **import only** (`IMPORT ALIEN 3RDPARTYFILTER`, no `EXPORT`), so
the open, save-as-the-same-format, reopen round trip the roadmap describes cannot be measured
until an OOXML exporter exists. Until then the harness measures **import fidelity**, with ground
truth read directly from the OOXML package by `run.py`, no external tool involved:

| Kind | Ground truth from the package | Compared with the loaded model |
| --- | --- | --- |
| `.docx` | top-level paragraphs and tables in `word/document.xml`, files under `word/media/`, footnotes with id > 0, all `w:t` text | paragraph enumeration, `TextTables`, `GraphicObjects`, `Footnotes`, `getText().getString()` |
| `.xlsx` | worksheets, cells with a value or formula, formulas, shared and inline strings | `Sheets`, `queryContentCells`, formula cells, string cells |
| `.pptx` | slides, `p:sp` shapes, all `a:t` text | `DrawPages`, shapes per page, shape text |

Plus, for every document: PDF export (page count and, with `poppler-utils`, text similarity
against the ground-truth text) and an **ODF round trip** (store as ODT/ODS/ODP, reload, check the
model facts survive).

## Scores

- A count feature scores 1 when equal, otherwise `1 - |got - expected| / max(expected, 1)`,
  floored at 0.
- Text features score the `difflib` similarity ratio of whitespace-normalised text.
- `load` is 1 or 0. A document that does not load scores 0 overall.
- A document's score is the mean of its features; the run's score is the mean over documents.

Output in the `fidelity-report` artifact: `report.json` (everything), `report.md` (the table,
also written to the job summary), and the exported PDF and ODF files.

## Corpus

`corpus/` holds:

- Real `.docx` files copied from `main/writerfilter/qa/documents`, one feature each.
- `synthetic-*.docx/.xlsx/.pptx` generated by `make_synthetic.py`, because the tree had no
  `.xlsx` or `.pptx` at all and the office cannot write them. Regenerate with
  `python3 make_synthetic.py corpus` when the generator changes; the output is reproducible.

Add real-world documents (charity accounts, grant reports, board packs, funder templates) only
when they may be published: keep files small, strip author metadata (`docProps/core.xml`), and
use feature-based names. Everything else stays in the local `test_files/` directory and is
measured with `run-local.sh`.

## Running locally, and private documents

Real documents often cannot be published. Keep them in `test_files/` at the repository root,
which is git-ignored, and measure them with the office CI just built:

```sh
test/fidelity/run-local.sh              # test_files/ -> .fidelity-local/out/report.md
test/fidelity/run-local.sh some/dir out # any directory
```

The script downloads the newest green `work-linux-x86_64-installed` artifact with `gh` (cached
under `.local-office/`), finds the Python version its pyuno was built for, and runs `run.py`.
Anything with `.docx`/`.xlsx`/`.pptx` in the directory is measured; nothing is copied into the
repository.

With an office already installed, set the environment the way `office_pyenv` in
`.github/scripts/linux-full-build.sh` does, then:

```sh
python3 test/fidelity/run.py <office_dir> test/fidelity/corpus <out_dir>
```
